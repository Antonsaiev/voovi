# Банковские выписки внутри Voovi

Скачивание не создаёт и не подписывает платёжные поручения. Сохранён прежний экспорт
1С из Центр-инвеста: профили `mi` и `ai`, только явно перечисленные расчётные счета,
за предыдущий календарный день по Москве.

## Сервисы и расписание

- `bank-selenium`: Firefox и Selenium Server `4.52.0-20261101`, без открытых host-портов.
- `bank-downloader`: Python 3.12 и Selenium Python `4.52.0`. Последняя версия клиента
  требует Python >=3.10, поэтому основной Django API на Python 3.9 не обновляется.
- `bank-download-tasks`: обычный Django background-tasks worker с `--queue bank_downloads`.
  Общий worker явно исключает эту очередь **до захвата задания**.
- Общий worker запускает лёгкий диспетчер раз в пять минут. Он ставит `mi` с 06:00,
  `ai` с 06:10. Первое автоматическое расписание после включения начинается со следующего
  06:00, если сегодня это время уже прошло. Повтор не меняет дату выписки.

Профиль и дата — часть идентичности задания. Параллельные диспетчеры защищены GET_LOCK.
Успешное или ещё существующее задание за этот день повторно не ставится.
У задания до трёх попыток очереди; внутри одной попытки до двух сессий для каждого
неуспешного счёта. Успешные счета сохраняются отдельно и при повторе пропускаются.
После окончательного сбоя задание остаётся с `failed_at`: нужен ручной повтор;
следующий день ставится независимо. Включение флага не запускает историческую догрузку.

## Передача файлов

Общий каталог проекта `var/bank/downloads`:

- `staging`: отдельная папка попытки; Firefox не пишет во входную папку импортёра.
- `ready`: только закрытые файлы, опубликованные атомарным rename.
- `archive`: исходники с SHA-256, сохраняемые независимо от последующего импорта.
- `state`: подтверждение результата по профилю, счёту и дате.
- `debug`: закрытые снимки ошибок. Снимки и старый staging очищаются через 7 дней
  при следующем запуске скачивания.

Файл должен стабилизироваться, содержать заголовок и конец 1С, корректные документы,
нужный расчётный счёт и **обе даты запрошенного периода**. Корректная пустая выписка
допускается. `.part`, `.tmp`, недописанные файлы и несоответствия не публикуются.
Передача не использует `docker cp` и не удаляет файлы после неуспешной копии.
Импорт/разнос продолжает существующий `task_import_bank_statements` раз в 300 секунд,
с прежними блокировками и защитой от повторных платежей. Скачивание само по себе
не означает, что каждый документ автоматически разнесён: ручные статусы видны в журнале импорта.

Все настройки и банковские учётные данные находятся в общих `configs/env/local.env`
и `configs/env/prod.env`. `BANK_DOWNLOAD_ENABLED=0` локально, `1` после production-приёмки.
Внутренний HTTP downloader требует `BANK_DOWNLOAD_TOKEN`; его порт не опубликован.
Полные реквизиты и документы в пользовательские логи не выводятся.

## Ручная проверка

Для production добавлять `-f docker-compose.prod.yml` и использовать `configs/env/prod.env`.

```sh
# Только показать профиль и дату; без входа в банк.
docker compose --env-file configs/env/local.env run --rm --no-deps svoovi-api \
  python manage.py download_bank_statements --profile mi --date 2026-11-06

# Реальный экспорт и публикация; повтор успешного дня берёт checkpoint.
docker compose --env-file configs/env/local.env run --rm --no-deps svoovi-api \
  python manage.py download_bank_statements --profile mi --date 2026-11-06 --run

# --force осознанно повторяет экспорт, например после дополнения выписки банком.
# Идентичный файл получает то же имя по SHA-256.
docker compose --env-file configs/env/local.env logs --tail 100 bank-downloader bank-download-tasks
```

У команды по умолчанию preview; ручной `--run` доступен и при выключенном автоматическом
расписании. На новой установке до `deploy.sh` создать `var/bank/downloads/ready` и
`var/bank/file_for_process`. При переносе сохраняются прежние файлы, `.bank-seen.json`
и незавершённые состояния; старые папки остаются резервной копией.

## Порядок переключения и откат

Перед переключением сохранить cron, Compose, ENV, исходники старого downloader и image ID.
Проверить реальный экспорт обоих профилей новой цепочкой и результаты передачи.
Только затем плавно остановить общий worker, скопировать его старые входные каталоги
в проект и запустить обновлённый worker. После проверки импорта отключить ровно три
старые cron-команды: `mi`, `ai`, `docker cp`/очистка. Старый `dockerbank` остановить,
исходники и резервные копии оставить.

При откате сначала отключить новое расписание и остановить **оба** банковских сервиса
и выделенный worker. Затем вернуть прежние Compose/ENV/images и восстановить старое
скачивание. Не включать две цепочки одновременно. Старую передачу с безусловным
`rm` после неуспешного `docker cp` не восстанавливать: копирование должно завершиться
успешно до очистки.

Версии проверены по официальным [загрузкам Selenium](https://www.selenium.dev/downloads/),
[PyPI](https://pypi.org/project/selenium/) и
[релизам docker-selenium](https://github.com/SeleniumHQ/docker-selenium/releases/tag/4.52.0-20261101).

## Общая папка web-загрузок (обновление 07.11.2026)

Банковские загрузки обоих web-интерфейсов направлены в одну папку проекта
`/root/docker/voovi/analitic/uploads/payments`. В прежний контейнер `analitic`
она подключена отдельным bind к `/code/uploads/payments`. Постоянная настройка
добавлена в его прежний production Compose, чтобы обычный перезапуск сохранял путь.
Новый интерфейс использует тот же источник через свой mount `./analitic/uploads`.
Из Compose Voovi удалено внешнее подключение `/root/analitic/uploads/payments`;
`BANK_LEGACY_UPLOADS_DIR` из production ENV удалён. Worker читает web-загрузки
один раз через `BANK_UPLOADS_DIR`, с прежними защитой от дублей и блокировкой.

Содержимое старой host-папки сохранено внутри `var/bank/migration-backups`.
Пустой каталог по старому host-пути оставлен как точка вложенного mount старого
контейнера; банковские файлы в нём больше не сохраняются. Рабочие выписки,
состояние обработки и данные импорта не удаляются.
