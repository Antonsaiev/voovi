# Исправления банковской автоматизации — 7 ноября 2026

Исправлены пять замечаний из [аудита](BANK_REVIEW_2026-11-07.md).
Изменения применены в `/root/docker/voovi` на production.

| Замечание | Исправление |
|---|---|
| Новые циклы попыток после окончательного сбоя | Диспетчер учитывает и успешную, и неудачную историю. Календарь поставленных дат сохраняется в банковском volume и не зависит от последующей очистки CompletedTask. После трёх ошибок нужен ручной повтор. |
| Пропуски после простоя | По каждому профилю догружаются отсутствующие даты с `BANK_DOWNLOAD_START_DATE=2026-11-07`, максимум семь дат на профиль за один проход. Даты до начала автоматизации автоматически не запрашиваются. |
| Успех при потерянном ready | Проверяются SHA-256, формат, счёт и период исходника. Отсутствующая или повреждённая копия ready/archive восстанавливается атомарно из второй проверенной копии. Если обе непригодны, возвращается ошибка с требованием явного `--force`. |
| Расхождение ограничения размера | Общая константа `MAX_STATEMENT_BYTES` в parser.py задаёт 16 MiB для downloader, браузерного ожидания и импортёра. Большой файл отвергается до публикации и отметки успеха. |
| Оставшаяся сессия после жёсткого таймаута | Родительский процесс удерживает общий flock до завершения дочернего процесса и очистки сессий выделенного Selenium Grid. Освобождение браузерного слота подтверждается отдельно; учтено асинхронное поведение Grid. Cleanup выполняется и при SIGTERM HTTP-сервиса. |

Дополнительно общий Django worker получил `stop_grace_period: 1900s`, как и
выделенный банковский worker; downloader — 60 секунд для контролируемой остановки.
Бизнес-логика импорта, разноса оплат и формирования чеков не изменялась.

## Проверки

- Локально и в точных production-образах: **26 тестов downloader** и
  **234 банковских теста Django**, без ошибок. 71 сценарий для отдельных MariaDB
  scratch-баз пропущен. Очередь проверена на настоящих моделях в SQLite в памяти.
- **3 теста deploy** локально и проверка production Compose — без ошибок.
- Новые сценарии: реальный `Task.reschedule` после третьей ошибки, очистка истории,
  простой на несколько дней, ограниченная догрузка, ошибка сохранения очереди,
  отсутствие/повреждение каждой копии выписки, обе испорченные копии, слишком
  большой файл, следующий счёт после большого файла, настоящий дочерний процесс
  с таймаутом, удержание flock во время очистки, остановка сервиса через SIGTERM.
- Настоящий Firefox локально и на production: открыт только `about:blank`,
  создан контролируемый таймаут, подтверждены завершение процесса, закрытие сессии
  и свободный браузерный слот. В банк эта проверка не входила.
