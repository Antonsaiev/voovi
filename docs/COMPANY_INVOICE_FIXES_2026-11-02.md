# Исправления продлений и отказов — 02.11.2026

Исправлены шесть согласованных пунктов проверки страницы `check.php` → «Таблица
счетов». Схема рабочей БД не менялась, миграций нет, реальные продления и отказы
при проверках не выполнялись. Production не обновлялся.

- Общий SQL отбора ожидающих продлений используется в счётчике и подробном списке.
  Счёт — одна строка на `rand`. Для «Все счета» открытые и ожидающие счета
  объединяются без повторного подсчёта пересечения.
- Смена организации, типа или дат очищает старые строки. Предыдущие запросы
  отменяются; поздние ответы от старого фильтра/фрагмента не подменяют новый список.
  После успешного отказа счётчики обновляются, старый список сбрасывается.
- Начальный период берётся из проверенных cookies, при отсутствии — текущий месяц.
  Тип по умолчанию «Продление». Первый запрос отправляет значения отображаемых
  полей. Флажок «Показать текущий месяц» устанавливает правильные календарные
  границы без преобразования локальных дат через UTC; обратный период не запрашивается.
- Статистика отказов сначала группирует активные отказанные позиции по `rand`,
  затем считает количество и итог С/К по причине. Общая цена не суммируется по
  каждому тарифу повторно. Все проценты рассчитаны из той же выборки; пустой
  результат не делит на ноль. Период статистики сохраняет прежнее назначение:
  дата создания счёта, а не дата отказа. Статистика представлена общей таблицей
  с долями и полосами распределения количества.
- «Сер/Пос» показывается одной строкой с обеими ожидающими частями и их точными
  датами. Уже продлённая часть не скрывает вторую; статус отражает частичное
  продление. Убраны сравнения только месяцев/годов концов диапазона и зависимость
  обновления после отказа от отсутствующих `naf/nayf`.
- Подписанный токен формы по-прежнему проверяется, но идемпотентность отказного
  клона привязана к исходному `rand` независимо от токена/пользователя. Используется
  существующая `schet_identity_keys`, без новой таблицы/индекса/колонки. Повтор
  неотгруженного отказа под блокировкой не переписывает причину, дату и автора.
  Исторический отгруженный источник с уже сохранённой датой отказа не клонируется
  повторно даже без нового ключа операции.

Удалена автоматическая подгрузка «Старых счетов» по всем месяцам начиная с октября
2020 года: она добавляла записи вне выбранного периода, размножала обработчики и
могла исчерпать память PHP. Старые счета не удаляются: для них нужно выбрать
соответствующий период в тех же фильтрах.
