# Локальная почта при DEBUG

configs/env/local.env использует DEBUG=true, production сохраняет DEBUG=0. KONTUR_AUTOMATION_NOTIFICATIONS_ENABLED=0 и REMINDERS_ENABLED=0 локально остаются дополнительной защитой.

При DEBUG API и аналитика используют django.core.mail.backends.locmem.EmailBackend: прямые вызовы Django не подключаются к SMTP. Собственные utils/send_mail.py в обоих проектах возвращают False до SMTP, чтения вложений и реквизитов. Вспомогательные старые вызовы вне настроенного Django читают DEBUG из ENV. Почтовый помощник Контура также возвращает False; успешная отправка и её отметка не имитируются. Напоминания возвращают unavailable с явной причиной, позволяя журналу показать отсутствие доставки.

Локальный compose подключает PHP debug-mail.ini с sendmail_path=/bin/false, поэтому встроенный mail() не вызывает настоящий транспорт. Обе используемые PHP SMTP-библиотеки при DEBUG возвращают False до формирования/отправки письма. Этот ini-файл подключён только в docker-compose.yml, не в production compose. Сетевая и банковская логика не менялась.

Проверки: 13 почтовых сценариев API, один сценарий аналитики и оба PHP SMTP-канала выполнены в контейнерах --network none с подменёнными транспортами. В работающих локальных API/worker/аналитике дополнительно подтверждены DEBUG=true, безопасный backend и отсутствие вызова SMTP. В PHP проверены оба SMTP-пути и отказ встроенного mail() через /bin/false с фиктивным адресом example.invalid. Реальных тестовых писем не отправляли.

Production в рамках этой локальной настройки не обновлялся. Полный production-подобный набор без сетевой изоляции был отклонён автоматической проверкой; вместо него выполнены целевые тесты без сети. Результаты прежних 1101 тестов не выдаются за повторный полный прогон после этой доработки.
