# Ежедневный гороскоп

Главная аналитики показывает общий ежедневный гороскоп Ignio на фактическую дату
Europe/Moscow. Случайные цитаты Forismatic и прописанный прокси больше не используются.

Источник: https://ignio.com/r/export/utf/xml/daily/com.xml
Условия: https://www.ignio.com/static/r/public/export/xml.html

Источник обновляется в 22–23 МСК. В XML `today` после вечернего обновления может
указывать на следующий день, поэтому дата читается из атрибутов `<date>`, а не
определяется по названию XML-элемента. На странице есть прямая ссылка на Ignio.
Поставщик также просит сообщить о подключении на export@ignio.com; автоматически
письмо не отправляется.

## Хранение и очередь

Схема БД не меняется, миграций нет. В существующей `background_task` хранится только
задание `basic.tasks.task_refresh_horoscope`. Общий worker регистрирует повтор раз
в час на ближайшую минуту :15 и одно задание для первого заполнения кеша. Регистрация
защищена существующей блокировкой worker и не создаёт повторных расписаний.

`HOROSCOPE_ENABLED=1` включён в root compose только у `svoovi-api-tasks`.
Каждый час проверяется необходимость загрузки: при наличии текущего прогноза
сетевых обращений нет. С 23:15 МСК выполняется вечернее обновление, при ошибке —
повтор не раньше часа. Файловая блокировка и сохранённое время попытки защищают
также от конкурентного ручного запуска и перезапуска контейнера.

Все прогнозы, результаты обновления и блокировка хранятся в постоянном Docker-томе
`voovi_horoscope`, отдельно от публичных uploads:

- worker: `/usr/src/app/var/horoscope`, чтение и запись;
- аналитика: `/code/var/horoscope`, только чтение;
- `forecasts.json`: прогнозы по ISO-датам, до 14 последних дат;
- `update.json`: время последней попытки и технический результат;
- `update.lock`: файловая блокировка.

Путь можно переопределить `HOROSCOPE_STORAGE_DIR` (он должен указывать на один общий
том у обоих процессов). Прогнозы и состояние обновления в БД не записываются.
Отдельный процесс или cron не нужен. Standalone compose аналитики подключает
существующий внешний том `voovi_horoscope`; его создаёт root compose.

## Отказы

HTTP идёт с сервера напрямую по HTTPS, без внешнего прокси и без cookies. Таймаут
15 секунд; размер XML ограничен 512 КБ. До замены кеша проверяются текущая дата,
вечером также следующая дата, и непустые тексты всех 12 знаков. Запись атомарная.
Неполный ответ или сетевая ошибка не затирает предыдущий успешный кеш.

Главная не делает HTTP-запросов и ничего не записывает в кеш. При отсутствии
сегодняшнего текста показывает последний доступный прогноз с его настоящей датой
и пометкой о задержке. При пустом кеше выводит сообщение о недоступности.
Будущие прогнозы до наступления соответствующей даты не показываются.

## Запуск и проверка

После обновления кода/образов применить root compose к аналитике и общему worker,
чтобы подключить том и `HOROSCOPE_ENABLED`. Production не обновляется этой
доработкой автоматически. Перед выкладкой проверить доступ к Ignio именно с
production-сервера без VPN. Не скачивать XML чаще раза в час.

Ручное обновление в worker: `python manage.py refresh_horoscope`.
Команда соблюдает тот же часовой лимит, файловую блокировку и не обращается к БД.
Технические ошибки видны в журнале `utils.horoscope` и `update.json`.

Автономные тесты файлового обновления: из API `python -m unittest utils.test_horoscope`.
Тесты чтения: из аналитики `python -m unittest utils.test_horoscope`.
`basic.test_horoscope_task` проверяет регистрацию существующей очереди с SQL и HTTP,
заменёнными заглушками. Для него требуется инициализированный Django.
