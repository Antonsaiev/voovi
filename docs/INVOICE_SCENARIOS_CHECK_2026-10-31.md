# Проверка выставления Савоира и присоединения Контура — 31 октября 2026

## Проверенные сценарии

| Сценарий | Результат |
| --- | --- |
| Счёт только Савоира | Сохраняются собственные `ns`, `rand`, сумма и тарифные строки. Документ и связь Контура не создаются. |
| К сохранённому Савоиру создают Контур | Создаются один документ в `bills`, его состав и одна связь `bills_voovi_links`. Ссылка сохраняется сразу по BillId. Номер, сумма, скидка, количество и строки Савоира не меняются. Внешнее создание проверено с подменённым клиентом, без реального счёта. |
| В обычное поле вводят номер известного счёта Контура | Общий сервис находит документ в локальной `bills`, сохраняет BillId и ссылку. Вручную указанная внешняя сумма не заменяется общим итогом Контура. Например, 456,78 ₽ остаются прежними при сумме документа Контура 789 ₽. |
| В то же поле вводят номер другого поставщика | Номер, сумма и пустая либо внешняя ссылка сохраняются. Связь Контура не создаётся, отсутствие документа не считается ошибкой. Отгрузка остаётся доступной. Правила ЗП не менялись. |
| Номер Контура пока отсутствует в локальной bills | Обычное поле остаётся внешним номером без новой ожидающей связи. Подходящая последующая новость позволяет распознать документ. Если использована специальная форма присоединения Контура, явная ожидающая связь с пустым BillId сохраняется до появления документа. |

Проверены оба обычных сериализатора API, старые PHP-блоки сохранения и отображение карточки. Уточнение типов денежных полей ЗП не меняет эти сценарии.

## Исправления по результатам проверки

1. `voovi.ru/komnete.php`: один непустой внешний номер больше не создаёт фиктивную карточку «счёта Контура». Без распознанной связи шапка показывает «Счёт поставщика» и сохраняет введённую ссылку.
2. `voovi.ru/js/kontur-card.js`: для сохранённой связи и старых записей с номером без link используется один тихий запрос существующего локального `status` API. Реальный документ отображается сразу, без ожидания cron. Неизвестный номер или недоступность поиска не показываются как ошибка счёта. Повторного запроса при раскрытии уже загруженного состава нет. Прежние HTML-реквизиты не выдаются за подтверждённые данные Контура после исчезновения связи. В том числе проверена прямая замена старым PHP уже связанного номера и ссылки на другого поставщика: старый состав до ответа скрыт, ложная подпись Контура не остаётся.
3. `voovi.ru/schet_identity.php`: отказной клон копирует имеющуюся связь Контура, включая явно ожидающую. По одному внешнему номеру новая ожидающая связь не выдумывается. Сами номер и ссылка в строках клона сохраняются; общий механизм сможет распознать их позже.

Правила оплаты, отгрузки, ЗП, расчёта АВ и нумерации этим исправлением не менялись. Новых таблиц, полей или настроек нет.

## Проверки и ограничения

- Полный API: **727 тестов**, без ошибок и пропусков. Из них четыре новых постоянных сценария находятся в `s.voovi.ru-api/basic/test_invoice_flows.py`; повторно проверены прежние сценарии ручной и ожидающей привязки, повторного выставления и мультипродуктовых счетов.
- Все **6 файлов JS-тестов** успешны. Проверки `voovi.ru/tests/kontur-card.test.js` и `supplier-invoice-display.test.php` охватывают распознавание старого номера, обычного поставщика, устаревшую связь и состояния created/pending/draft/rejected.
- Успешен общий PHP-набор в отдельной `voovi_schet_identity_test_supplier_20261031`: настоящие блоки POST для трёх вариантов обычного счёта (только Савоир, введённый номер Контура, другой поставщик), по две тарифные строки с итогом 720,00 ₽. Повтор каждого POST не создаёт дубль. Дополнительно проверены 48 параллельных выдач номера, четыре параллельных повтора формы, клоны, rollback при сбое, сохранение АВ и метаданных, печать и прежняя отгрузка. После проверки временная база удалена.
- Записи выполнялись только в выделенных тестовых базах. Реальные обращения к Контур API и отправка уведомлений запрещены. Production, рабочие локальные начисления и счета не менялись.
- Окончательный приём реального состава и доступность продажи конкретного тарифа определяет API Контура. Эти проверки подтверждают поведение нашего кода на заданных ответах, а не создают новые production-счета.
