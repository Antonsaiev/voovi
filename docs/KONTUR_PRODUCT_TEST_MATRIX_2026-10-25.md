# Тестирование счетов с разными продуктами

Все сценарии выполняются на `voovi_kontur_v1_test`. Реальные обращения к API подменены;
рабочие счета, оплаты и уведомления не создаются. Цены и доступность в фикстурах синтетические:
проверяется поведение Voovi, а не действующий прайс или совместимость продуктов в Контуре.

Код: `s.voovi.ru-api/basic/kontur/test_product_scenarios.py` и
`voovi.ru/tests/kontur-product-scenarios.test.js`.

## Успешное выставление

| Состав | Проверки |
| --- | --- |
| КЭП на 6, 12 и 15 месяцев | Разные суммы, сохранённый срок |
| КЭП с сопровождением | Основной тариф и дополнение в расчёте и отправке |
| Диадок | Отдельный счёт с собственным лицевым счётом |
| ОФД | Отдельный счёт, точность суммы до копеек |
| 13 носителей | 13 пакетов с разными идентификаторами, без регистрации ЛС |
| Услуга с открытой ценой | Цена сохраняется и попадает в запрос создания |
| КЭП с сопровождением + 13 носителей | Один счёт, 15 пакетов с учётом дополнения |
| КЭП + Диадок | Отдельный расчёт каждого продукта, один запрос создания |
| КЭП + Диадок + ОФД + носители | Сумма, количество и ЛС каждого продукта |
| Одинаковые коды тарифов разных продуктов | Названия и цены не смешиваются |
| ОФД + Диадок + ОФД | Сохраняется порядок позиций, ОФД рассчитывается одним запросом |
| Две КЭП с сопровождением + два носителя | Количество, дополнения и уникальные GUID |

Матрица содержит 14 успешных вариантов. Каждый проверяет сохранение состава в таблицах,
ссылку на созданный счёт, неизменность суммы Voovi и отсутствие повторной отправки при втором нажатии.

## Ошибки и повторная обработка

- 12 вариантов неверных параметров: срок, количество, открытая цена, неизвестный продукт,
  чужое дополнение и превышение общего лимита 500 единиц.
- Подготовка отсутствующего ЛС один раз перед созданием смешанного счёта.
- Отказ по продукту или ошибка второго расчёта сохраняют предыдущий полный состав.
- Отказ объединения продуктов позволяет изменить состав и создать исправленный счёт.
- Неопределённый результат создания не приводит к повторной отправке.
- Старый расчёт нельзя выставить после изменения срока.
- Пропавшее, лишнее или заменённое дополнение и переставленные тарифы не принимаются как актуальный расчёт.
- Лента заполняет номер, сумму, оплату, пакеты и услуги смешанного счёта без дополнительных HTTP-запросов.
  Повтор той же новости не проставляет оплату повторно.
- REST API возвращает полный состав. Форма восстанавливает продукты, количество, параметры и открытую цену.

В тестах найден и исправлен случай принятия ответа расчёта без выбранного дополнения.
Теперь перед сохранением проверяется соответствие всего дерева тарифов и дополнений.

## Повторный запуск

Нужна заранее подготовленная тестовая БД с [актуальной единой схемой `bills*`](KONTUR_UNIFIED_STORAGE_2026-10-26.md) и необходимыми таблицами Voovi.
Проверка в `setUp` запрещает очистку любой базы с именем, отличным от `voovi_kontur_v1_test`.

```sh
docker exec apisvoovi sh -c 'SQL_USER=root SQL_PASSWORD="$MYSQL_ROOT_PASSWORD" SQL_DATABASE=voovi_kontur_v1_test python manage.py shell -c "import unittest; result = unittest.TextTestRunner(verbosity=2).run(unittest.defaultTestLoader.loadTestsFromName(\"basic.kontur.test_product_scenarios\")); raise SystemExit(not result.wasSuccessful())"'
node voovi.ru/tests/kontur-form-core.test.js
node voovi.ru/tests/kontur-product-scenarios.test.js
```
