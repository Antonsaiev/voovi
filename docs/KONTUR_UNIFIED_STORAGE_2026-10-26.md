# Единое хранилище счетов Контура

Счета из новостей и счета, созданные через Voovi, хранятся в общих `bills*`. Один документ определяется уникальным `bills.BillId`; несколько счетов Voovi могут ссылаться на него без копирования состава. Таблицы Django unmanaged. Одноразовое обновление их структуры завершено, механизм подготовки удалён; миграции Django для них не применяются.

## Таблицы

- `bills` — документ Контура: номер, плательщик, партнёр, внешние менеджеры, оплата, учётная сумма. Добавлены `currency`, `amount_without_vat`, `vat_amount`, `request_hash`, `created_at`, `status`, `revision`, `quote_amount`, `created_by`, `last_error`, `updated_at`. `created_by` хранит ID сотрудника Voovi, фактически отправившего счёт; пустой менеджер в новости не стирает его.
- `bills_tariffs` — тарифы, дополнения, количество, цены, сроки, получатель и лицевой счёт. Локальный `id` — первичный ключ; внешний `BillTariffId` остаётся уникальным и может быть NULL до получения новости. Дополнения связаны через `parent_id`.
- `bills_tariffs_services` — учётные строки услуг. Сохранены исходный ключ `BillTariffRowId` и связь с тарифом через `BillTariffId`.
- `bills_order_packages` — пакеты заказа; исходный `Id` сохранён.
- `bills_properties` — параметры выбранных тарифов и пакетов отдельными строками.
- `bills_discounts` — скидки; `source` обозначает происхождение скидки.
- `bills_voovi_links` — `id`, уникальный `schet_rand`, nullable `BillId`, `legacy_number_before`, `legacy_amount_before`, `legacy_published_at`.
- `bills_operations` — только `id`, `BillId`, `kind`, `request_body`, `finished_at`, `error`. Хранится актуальный запрос расчёта или создания и необходимая защита регистрации лицевого счёта (`account_*`). История ответов, HTTP-коды, trace ID, счётчики и отдельная ревизия операции не сохраняются.

## Этап документа и повторная отправка

Проверки используют `status`: `draft`, `sending`, `created`, `unknown`, `rejected`, `deleted`. `revision` определяет актуальность расчёта, `request_hash` проверяет его целостность. Наличие учётного итога определяется по `Amount IS NOT NULL`; ноль считается заполненной суммой.

До запроса создания сохраняются GUID, точный запрос и `status='sending'` под блокировкой строки InnoDB. Неопределённый ответ переводит документ в `unknown`; повторный вызов не отправляет новый запрос. После явного отказа новый расчёт получает новый GUID.

## Присоединение существующего счёта

Поиск в форме использует локальные `bills`: номер, ИНН или название плательщика, до 20 результатов; точный номер первый. Черновики и удалённые документы исключены. При выборе создаётся только связь с `BillId`. Отличие ИНН/КПП показывается предупреждением и допускается после явного подтверждения. Создатель документа не подменяется сотрудником, выполнившим присоединение.

Если номер ещё не найден, сохраняется ожидающая связь с `BillId=NULL`. Единственное место хранения введённого номера — `schet.nomerschetks`. Новое выставление для этой группы заблокировано. При сохранении номера сервер повторяет поиск: если счёт появился после открытия формы, `BillId` присоединяется сразу.

При новости `schetmain` ищет ожидающие группы по текущему `schet.nomerschetks`, затем проверяет все активные строки группы. Неоднозначные документы и расходящиеся номера не привязываются автоматически. Если номер изменили, используется новый номер; очищенный номер не восстанавливается. Перед привязкой повторно проверяется актуальность данных группы. Уникальный индекс `schet_rand` защищает от двух связей одной группы.

## Дополнение из новостей

Лента дополняет отсутствующие поля и строки общего документа. Существующий состав и заполненные реквизиты сохраняются; статус оплаты, видимость и позиция изменения обновляются. Учётный итог сохраняется отдельно от предварительного расчёта.

Номер и ссылка дополняются во всех связанных группах Voovi. Существующие `schet.priceks`, включая ноль, сохраняются даже при отличии от общей суммы Контура. Пустую сумму можно дополнить общим итогом только при одной связанной группе; при нескольких группах распределение не выполняется автоматически. При подтверждённой оплате дополняется недостающая отметка с датой. Удаление в Контуре снимает связи; документ остаётся со статусом `deleted` для защиты от запоздавших новостей.

Отдельного опроса по кнопке или автоматической проверки документа через иной API нет. Если новость о документе не поступит, ожидающая связь сама не завершится.

## Применение SQL

Структура production обновлена 30 октября 2026 года; [результат и проверки](PRODUCTION_DATABASE_UPDATE_2026-10-30.md). Одноразовые скрипты и планы обновления удалены. `./dev.sh start` и `./deploy.sh` запускают приложения без автоматического изменения структуры базы. Для новой локальной установки используется актуальный `voovi.sql`.

После подготовки добавляются недостающие `bills_voovi_links` для сохранённых счетов `schet`, если номер Контура однозначно соответствует документу в `bills`. Имеющиеся связи и суммы не меняются. Неоднозначные группы требуют отдельного разбора.

Черновики имеют NULL в ещё не полученных учётных полях; внешним выборкам выставленных документов нужен фильтр по номеру или статусу.

## Локальная проверка

Подготовка схемы проверяется на отдельной БД: первый запуск создаёт недостающие части, повторный не планирует уже применённые DDL. Регрессионные тесты используют отдельную БД `voovi_kontur_v1_test` и запрещают внешние HTTP-запросы; сценарии описаны в [матрице тестирования](KONTUR_PRODUCT_TEST_MATRIX_2026-10-25.md).
