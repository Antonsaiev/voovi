**Статус: применено на рабочем сервере 29 октября 2026 года.** Проверены SHA-256 всех 20 установленных PHP-файлов, сохранение владельцев и прав, успешный пробный обратный патч. Серверный lint прошёл в `/usr/bin/php`, `/opt/php71/bin/php`, `/opt/php73/bin/php`. База данных и процессы приложений не менялись. В закрытом каталоге сопровождения сохраняются инструкция и обратимые патчи; временные исходники и установщик удалены. Отдельная последующая замена домена описана ниже.

## Назначение и область изменений

По поручению пользователя в старой серверной PHP-версии временно отключаются:

1. Редактирование существующих счетов через прежние формы состава и реквизитов.
2. Создание отказов, включая отдельный обработчик и массовые действия старых списков.
3. Автоматическая замена `schet.idkli` при просмотре четырёх страниц.

Рабочий каталог старой версии: `/var/www/voovi/data/www/voovi.ru/`.
Изменения подготовлены по фактическим серверным исходникам от 29 октября 2026 года, а не по текущему PHP-проекту в Git. Изменены 20 PHP-файлов. Новая PHP-версия в локальном репозитории не заменяется серверными исходниками.

Исходные отключённые операции сохранены в комментариях с общим маркером **`TEMP_LEGACY_20261029`**. Для точного отката сохранён прямой патч, который применяется с `--reverse`.

Файлы сопровождения на сервере, вне публичного сайта:

- `/var/www/voovi/data/maintenance/legacy-compatibility-2026-10-29/README.md` — эта инструкция;
- `/var/www/voovi/data/maintenance/legacy-compatibility-2026-10-29/restrictions.patch` — обратимый патч всех 20 файлов.
- `/var/www/voovi/data/maintenance/legacy-compatibility-2026-10-29/analytics-domain.patch` — отдельный патч последующей замены домена аналитики.

Копия патча в репозитории: `docs/legacy-php/20261029_restrictions.patch`.

SHA-256 патча: `63394a06d093b4e5ef1f14ba1b1882c56fea5da3ed1cbcd3115078b6e870eb58`.

## Что именно отключено

### Старое редактирование счетов

| Файл | Изменение |
| --- | --- |
| `newschet.php` | Запрос с `GET[rand]` или `POST[submitsave]` отклоняется с HTTP 403 до подключения конфигурации и SQL. Новый счёт без этих признаков проходит в прежний обработчик. |
| `myogrn.php` | Такой же ранний запрет, до изменения счётчика, состава, АВ и журнала. Исходное условие `if(isset($_POST['submitsave']))` сохранено комментарием; его большой блок дополнительно закрыт `if (false)`. Закомментирован вывод кнопки «Сохранить» существующего счёта. |
| `otherogrn.php` | Ранний запрет существующего `rand` и `submitsave`, в том числе при прямом обращении к файлу. Это не даёт отправить прежнюю форму существующего документа через альтернативный обработчик. |
| `setschet.php` | Закомментированы исходные `echo` ссылок «Изменить список продуктов» и «Изменить данные». Просмотр состава оставлен. |
| `schetdataedit.php` | Прежняя отдельная форма редактирования реквизитов временно закрыта до конфигурации и SQL. |
| `pusya.php` | Закрыт только запрос с `date_schet`, используемый прежней формой даты. Исходное условие этой ветки закомментировано, тело дополнительно закрыто `if (false)`. Остальной общий обработчик не отключён. |

Прямые URL и сохранение из ранее открытой вкладки также попадают под серверный запрет. Это не ограничение только кнопок.

Создание **нового** счёта без `rand` и `submitsave`, включая создание с `oldns`, не отключается. Подстановка существующего `shetrand` в прежний обработчик создания остаётся отдельным старым дефектом: эти временные ограничения не заменяют будущую проверку идентичности и общий аллокатор.

Патч ограничений не закрывает ссылку `inctoha.php` на Django `/payments/EditTarifSchet`: она ведёт в другую реализацию. Последующий доменный патч меняет только её адрес. Комментарии, контакты, назначения менеджера, оплаты и отгрузки не блокировались этим изменением. Имя `submitsave` в `call.php` относится к организации, поэтому этот обработчик не затронут.

Просмотр отказных счетов и фильтры сохранены. Все 11 прежних веток возврата `otk/cher=0` оставлены дословно; скрытые массовые кнопки больше не предлагают переключение статуса. Процесс `call_center.otk` не относится к отказу счёта и не менялся.

### Автоматическая замена клиента

В `setschet.php`, `1toha.php`, `tohaakt.php`, `serchtohaakt.php` закомментированы ровно четыре автоматических `UPDATE schet SET idkli=...`, выполнявшихся при просмотре. Исходные запросы сохранены между маркерами `BEGIN/END AUTO_CLIENT_REASSIGN`.

Чтение клиента и отрисовка страниц не меняются. Позднее заполнение старого `ns` не отключалось: оно не относится к замене клиента.

## Проверки

- Все 20 подготовленных файлов прошли синтаксическую проверку PHP 5.6 в локальном контейнере.
- Проверены 27 сочетаний URL/POST: старые формы и прямое сохранение блокируются; запросы создания нового счёта и другие операции `pusya.php` достигают прежнего обработчика. Вместо конфигурации использована заглушка: тесты не подключались к рабочей базе и не создавали документы.
- Реальные фрагменты всех 11 массовых обработчиков выполнены с SQL-заглушкой: установка отказа не выполняет SQL; возврат статуса даёт тот же запрос и результат, что исходная версия.
- PHP-токенизация подтвердила отсутствие исполняемого автоматического изменения `schet.idkli` на четырёх страницах.
- Проверено скрытие 32 отдельных и 7 массовых кнопок.
- Прямое и обратное применение патча воспроизводит все 20 файлов побайтно; проверены SHA-256.
- При применении на сервере сверяются исходные SHA-256 всех файлов; несовпадение останавливает установку до изменения сайта. Перед заменой выполняется серверный PHP lint, после — проверка установленных файлов и пробный обратный патч.

Изменения не требуют обновления БД, установки триггеров, Django migrations или запуска фоновых задач. Существующие документы и их данные этим применением не изменяются. Сам факт успешных тестов не означает полной совместимости всех остальных операций старого PHP с новой схемой.

## Полный откат временных ограничений

Для полного возврата обоих изменений сначала откатить отдельный доменный патч по предыдущему разделу, затем патч ограничений по командам ниже. Перед каждым шагом выполнять собственный dry-run на текущих файлах; при конфликте остановиться. Патчи хранятся отдельно и не переписываются задним числом.

Команды выполняются по SSH на сервере с правами записи в старый проект. Указанный патч не предназначен для применения к новой PHP-версии из текущего Git.

Сначала проверить, что обратный патч применим к текущим файлам:

```sh
cd /var/www/voovi/data/www/voovi.ru/
patch --dry-run --batch --fuzz=0 --reverse -p1 \
  -i /var/www/voovi/data/maintenance/legacy-compatibility-2026-10-29/restrictions.patch
```

Только при успешной проверке выполнить:

```sh
patch --batch --fuzz=0 --no-backup-if-mismatch --reverse -p1 \
  -i /var/www/voovi/data/maintenance/legacy-compatibility-2026-10-29/restrictions.patch
```

Патч возвращает исходный код всех 20 файлов; откат не меняет записи базы данных. Затем проверить синтаксис изменённых файлов тем PHP, который используется сайтом, и обновить открытые вкладки.

Если dry-run сообщает конфликт, не применять `--force` и не подменять целиком файл старой копией: после этих ограничений в него могли внести другие изменения. В таком случае вернуть только нужные участки по маркерам ниже либо адаптировать патч, сохранив последующие правки.
