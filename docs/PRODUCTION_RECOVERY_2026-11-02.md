# Исправление фоновых задач — 2 ноября 2026

Причины: DeliveryPartnerId в ленте является UUID, но обе модели bills и БД ожидали int; ValueError одного документа прерывал ленту; HTTP 400 одного клиента прерывал поиск идентификаторов; очередь скрывала ошибку за техническим завершением; Docker-журналы не имели лимита.

Изменения:

- API basic/kontur_models.py и basic/models.py: DeliveryPartnerId — VARCHAR(36), прежние числовые ID сохраняются строками.
- basic/kontur/storage.py: даты нормализуются в aware datetime с прежней интерпретацией Europe/Moscow.
- jobs/schetmain.py: ValueError и ValidationError данных сохраняются как news_retry отдельно, следующие документы продолжаются. Ошибки БД не перехватываются; курсор при инфраструктурном сбое не продвигается.
- jobs/search_abonentId.py: HTTP 400/422 и неоднозначные реквизиты пропускаются по клиенту с ID/причиной; 401, ошибки соединения и сервера прерывают запуск.
- runtime.py и команда kontur_automation: атомарные файлы `<job>.result.json` в существующем томе Контура. Поля job/status/started_at/finished_at/last_success_at/error; ошибка сохраняет прежний last_success_at. Повреждённый диагностический JSON восстанавливается. Курсор хранится отдельно и не сбрасывается.
- docker-compose.yml / docker-compose.prod.yml: json-file, max-size=10m, max-file=5. Старые журналы сохраняются перед заменой контейнеров. Для применения к уже работающему контейнеру требуется пересоздание.
- Исправление отправителя рассылки infosavoir@yandex.ru закреплено в ENV; пароли не менялись.

Проверки: новые тесты воспроизвели сбои до исправления. Локально 1065 тестов без ошибок, 71 отдельная интеграция пропущена. Репетиция pt-online-schema-change на изолированной MariaDB 5.5.68 прошла, прежний числовой ID 1878 сохранён, временные триггеры сняты.

Развёртывание: снимок bills в согласованной транзакции, резервные образы, полные журналы текущих контейнеров, ENV/compose/курсор в `/root/voovi-releases/recovery-20261102`. Для production применяется только онлайн-изменение колонки с lock_wait_timeout=1, innodb_lock_wait_timeout=1 и контролем нагрузки. Старый вариант таблицы был сохранён для сверки, затем выгружен в отдельный дамп и удалён. Дамп рабочей базы не восстанавливается.

Семь ручных банковских отказов не изменяются, финансовые правила, старые сайты и AgentKKT сохраняются.
