## Что установлено

- Банковская обработка перенесена в общий worker: разбор выписок, импорт, разнесение, полные возвраты, сохранение исходников, checkpoint, отдельная история по месяцам и восстановление после прерывания. Настройки и принятые правила — [BANK_PAYMENTS.md](BANK_PAYMENTS.md).
- Новая ручная загрузка атомарно сохраняет файл и ставит ближайшую задачу. Несколько загрузок обслуживаются одной очередью. Плановый запуск выполняется каждые пять минут.
- Доработаны ручной разнос и возврат, расширенный просмотр распределений, поиск истории оплат и защита действий с чеками от повторного подтверждения.
- Сохранённая стоимость строк используется в чеках, документах, Бухгалтерии и ЗП. При отсутствии JSON сохранён прежний расчёт по тарифу. Единичная цена печатается с копейками; при необходимости сумма разбивается на две печатные позиции, количество и итог сохраняются.
- Исправлены обработка номера счёта с ведущими нулями и печать прежних вариантов выезда. AgentKKT не обновлялся.

## Переключение банковской обработки

Сначала собраны образы и выполнены изолированные проверки. До этого банк в новой конфигурации был выключен. Затем в root-crontab закомментированы ровно три заменяемые строки:

1. Копирование ручных загрузок из двух версий аналитики в `Downloads`.
2. `/root/selenium-compose/files/convert.py`.
3. `/root/selenium-compose/files/scriptautopayment`.

Проверено отсутствие работающих прежних обработчиков. После этого включён `BANK_AUTOMATION_ENABLED=1` и заменены четыре контейнера. Старый общий worker `apisvoovi_tasks` остаётся остановленным.

Вход в банк, скачивание и `docker cp dockerbank:.../Downloads` остаются на сервере по прежнему расписанию. Новый worker получает:

| Источник на сервере | Назначение |
| --- | --- |
| `/root/selenium-compose/files/Downloads` | Серверные выписки |
| `/root/selenium-compose/files/file_for_process` | Прежние подготовленные файлы |
| `/root/docker/voovi/analitic/uploads/payments` | Загрузки новой аналитики |
| `/root/analitic/uploads/payments` | Загрузки прежней аналитики |

Четвёртый вход добавлен для сохранения работы прежней формы загрузки. Её код не менялся. Внешние исходники сохраняются на месте; новый worker хранит собственные снимки и состояние в `voovi_voovi_banking`.

В очереди — 11 регулярных задач, включая ровно одну банковскую с `repeat=300`. Первый плановый банковский запуск выполнен **01.11.2026 в 22:27:36 МСК**: `files=0`, `payments=0`, `errors=0`, `pending=0`, `retries=0`; создан один следующий повтор. Выписок в этот момент не было.

## Проверки

Локальные наборы регрессии выполнены до отправки изменений. Дополнительно именно собранные production-образы проверены на отдельной MariaDB **5.5.68**, без портов, доступа к рабочей БД и внешнему HTTP/SMTP:

- API: **833 теста**, без ошибок и пропусков; использована копия схемы production без данных.
- Банк и worker: **230 тестов**. Один тест на дописывание 400 документов сначала достиг 30-секундного лимита при ограниченном CPU; отдельный повтор с тестовым лимитом 180 секунд прошёл. Рабочий лимит остался 30 секунд. Остальные 229 тестов прошли с первого раза.
- Аналитика: **279 тестов**, 274 прошли, пять интеграций имеют отдельную защищённую БД; дополнительный набор из восьми тестов на этой БД прошёл, включая эти пять. Реальные конкурентные операции проверялись только в тестовых БД.
- PHP: полный набор создания, редактирования, отказов, сохранности АВ, исторических номеров, выездов и печатных вариантов; 48 конкурентных выделений номера и четыре повтора формы. Денежная арифметика и PHP lint прошли.

После замены:

- Базовая production-приёмка — **33/33**: образы, Django, read-only подключение к БД, авторизация, PHP, статика, старые сайты и контрольные суммы AgentKKT.
- Авторизованная отрисовка восьми страниц/маршрутов оплат и ЗП выполнена с запретом SQL-записи и внешнего HTTP/SMTP, без JavaScript фоновых кнопок. Операции изменения чека через GET возвращают 405.
- Внешний HTTPS: PHP — 200; аналитика без авторизации — ожидаемый 302. Внешний HTTPS проверен с клиентской машины через действующий входной маршрут.
- Все четыре новых контейнера работают без перезапусков. В API зарегистрированы ожидаемые PermissionDenied/403 от анонимных smoke-запросов; неожиданных ошибок старта не найдено.
- Исходные контейнеры `apisvoovi` и `analitic` сохранили ID и образы. Четыре конфигурации Apache и все файлы AgentKKT сохранили контрольные суммы. Общие тома Контура и ЗП сохранены; cursor и расписания не переинициализировались.

Рабочие счета, оплаты, возвраты, начисления и физическая касса в приёмочных тестах не изменялись. Проверка с настоящей банковской выпиской и физической кассой не выполнялась. Автоматические служебные записи очереди и банковского журнала созданы штатным worker.

## Материалы и возврат к прежней версии

Приватный каталог сервера: `/root/voovi-releases/20261101-220610` (доступ root). В нём сохранены исходные архивы четырёх репозиториев, ENV, compose, crontab до/после, файлы AgentKKT, снимки контейнеров, Git bundles, журнал сборки, изолированные проверки и production-smoke.

Образы до обновления закреплены тегами `voovi-rollback/<имя контейнера>:20261101-220610`. Перед их возвратом нужно остановить новые финансовые задачи, сохранить банковский том и проверить незавершённые платежи/чеки. Старые три cron нельзя включать одновременно с новым банковским обработчиком. После появления реальных новых операций их состояние нужно проверить перед возвратом прежнего банковского скрипта. Восстановление БД из старого дампа для отката кода не требуется и не выполнялось.

После репетиции удаляются только созданный изолированный контейнер MariaDB и его анонимный том. Приватные журналы и резервные образы сохраняются для диагностики и отката.
