Уже подтверждённые письма повторно не отправляются. Если после начала передачи SMTP подтверждение потеряно, событие имеет статус unknown: перед повтором нужно проверить доставку. Недоступность SMTP не останавливает другие фоновые задания; результат содержит ошибку, суточное расписание продолжается.

Резервные копии и протоколы на сервере: /root/voovi-releases/reminders-20261102, доступ только root. Сохранены исходные crontab, ENV/compose, схема, предыдущие исходники, идентификаторы контейнеров, тесты, preview и smoke. Предыдущие API/worker сохранены тегами voovi-rollback/*:before-reminders-20261102. Изолированная тестовая БД удаляется после приёмки, production-данные из неё не восстанавливаются.

## Откат

Сначала REMINDERS_ENABLED=0 и безопасная остановка worker после завершения активной задачи. Удалить только три ожидающие basic.tasks.task_invoice_reminders либо оставить их выключенными флагом. Если требуется, вернуть предыдущие образы. Только после остановки новых проверок раскомментировать три исходные cron-строки, учитывая уже отправленные за день письма. Нельзя запускать оба обработчика одновременно. Журнал и production-данные не удалять.

Первые реальные выполнения будут по следующему расписанию; успешная приёмка не означает, что завтрашние письма уже отправлены.
