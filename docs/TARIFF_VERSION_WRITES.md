# Изменение версий тарифов

PHP-форма и API сохраняют изменения группы/складской модели созданием новой версии
`tarif` с тем же `sync_id`. Старые счета сохраняют `schet.prod`: исторические строки
не получают новые группу, модель или цену. Родитель обновляется вместе с версией.
Название существующего тарифа через эти операции не меняется.

Сохранение прежних значений возвращает текущую версию. PHP сравнивает весь
нормализованный состав полей, API — изменяемые поля метаданных. Повтор прежнего
API-запроса возвращает уже созданную версию, если запрошенные поля совпадают;
конфликтующее изменение устаревшей версии возвращает 409.

API-ответ содержит новый `id`. Интерфейс складских настроек сохраняет его для
следующего редактирования и показывает выбранное значение только после успеха.
При ошибке значение восстанавливается. Цена и название в этом API остаются read-only.

Текущая версия — источник значений группы, модели и описания. Если родитель был
рассинхронизирован старым API, последующее сохранение синхронизирует его с текущей
версией; отдельная массовая правка справочника при старте приложения не выполняется.
PHP-список также читает эти значения из текущей версии, включая явный NULL модели.

## Требование к схеме

Для атомарного отката **обе** таблицы `tarif` и `tarif_parent` должны быть InnoDB.
На прежней схеме MyISAM новая операция откажет до первой записи.
Явное обновление — `database/migrations/2026-11-08_tariff_versions_innodb.sql`.
Перед ним сохранить полный дамп таблиц, SHOW CREATE TABLE и контрольные суммы
всех строк, после — сверить. ID, значения тарифов и ссылки счетов не меняются.
Изменение движка выполняется отдельно; оно не запускается из web-запроса.

Каждая операция начинает транзакцию и блокирует родительскую строку через
SELECT FOR UPDATE. Оба приложения используют одинаковый порядок блокировок.
Создание версии, архивирование прежней и обновление родителя фиксируются вместе.
При ошибке INSERT, архивирования или изменения родителя изменения откатываются.
Создание и архивирование родительской карточки в PHP также транзакционны.

Работа над общими тарифами нескольких продуктов не выполнялась. Защита PHP-формы
от устаревшей вкладки, денежная валидация, права/CSRF и замена правил с жёстким ID
тарифа остаются отдельными вопросами исходного аудита, не входят в эти четыре правки.

## Проверка

`basic.test_tariff_versions` работает только в явно выделенной базе
`voovi_tariff_versions_test`; таблицы tariff должны быть подготовлены из текущей
схемы. `voovi.ru/tests/tarif-versions.test.php` использует ту же отдельную базу.
Тесты очищают исключительно её справочники. Боевые данные для фикстур не нужны.

Проверяются отсутствие новых версий без изменений, новая группа/модель с сохранением
истории, очистка модели, ремонт родителя, повтор API, INSERT/UPDATE failures,
отказ на MyISAM. Для PHP ошибка архивирования проверяется настоящим тестовым
триггером, ошибка INSERT — ограничением колонки в строгом SQL-режиме.
