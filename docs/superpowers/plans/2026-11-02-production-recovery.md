# Восстановление фоновой обработки production

Цель: устранить подтверждённые ошибки аудита без изменения финансовых правил.

- [ ] Тестами воспроизвести UUID в DeliveryPartnerId и некорректные данные отдельной новости.
- [ ] Обе модели bills перевести на строковый идентификатор; подготовить точечный SQL VARCHAR(36), сохраняя прежние числовые значения.
- [ ] Ошибки данных сохранять для повтора по документу; ошибки БД не скрывать и курсор не продвигать. Нормализовать даты с часовым поясом.
- [ ] Поиск клиентов: отказ валидации одного клиента не прерывает остальных, инфраструктурные ошибки остаются ошибками запуска; логировать ID клиента и безопасную причину.
- [ ] Сохранять отдельный результат каждого запуска Контура (успех/ошибка/время), не ломая регулярные повторы.
- [ ] Задать ограничение Docker-журналов и сохранить прежние журналы перед заменой контейнеров.
- [ ] Прогнать регрессию в отдельной локальной БД без HTTP/SMTP, проверить MariaDB 5.5.
- [ ] Сделать резервные копии production, установить исправления, проверить продвижение существующего курсора и остальные задачи; записать результат.

Ограничения: не менять ручные банковские отказы, суммы/оплаты/ЗП, старые сайты и AgentKKT. Не сбрасывать курсор и не запускать дубли worker. Изменение колонки на production допустимо только без блокировки пользователей; перед ALTER проверить размер и доступный онлайн-алгоритм MariaDB 5.5.
