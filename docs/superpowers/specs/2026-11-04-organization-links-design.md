# Страница связей организаций

## Задача

Оформить `voovi.ru/svyaz.php` в общем стиле `komnete.php`, сохранив поиск и действия привязки, перепривязки и отвязки.

## Компоновка

```text
Карточка клиента                            Назад к клиенту
Связанные организации
Название организации / ИНН

Связанные организации
Название                 ИНН / КПП        ОГРН       Действие
[Если связей нет — понятное сообщение]

[Название, ИНН, КПП или ОГРН — поиск при вводе]
Название                 ИНН / КПП        ОГРН       Привязать
Страницы
```

Выравнивание слева. Основная организация получает спокойную метку. Название ведёт в карточку клиента. Номер внутренней записи не занимает отдельную широкую колонку. На телефоне форма складывается в одну колонку, прокрутка таблицы остаётся внутри блока.

## Визуальная система

- Фон: `#f4f6fa`.
- Белая поверхность: `#ffffff`.
- Голубая шапка: `#e1eaf4`.
- Мятный акцент: `#dceee5`.
- Основной текст: `#344d60`.
- Границы: `#dce4ec`.
- Шрифт: Segoe UI, Verdana, sans-serif — как в карточке счёта.
- Заголовок 26 px, разделы 18 px, основной текст 14–15 px.
- Небольшие скругления, чёткие подписи полей, заметный фокус клавиатуры; без декоративных изображений и анимаций.

## Подходы

1. Только перекрасить две существующие колонки. Минимальные изменения, но две таблицы продолжают сжимать названия и реквизиты.
2. Последовательные полноширинные разделы: текущие связи, затем поиск и организации для добавления. Рекомендуемый вариант: сразу виден результат, достаточно места для реквизитов.

## Ограничения и проверка

Сохранить действующие URL обработчиков и смысл операций. Не менять данные или связи ради проверки оформления. Изолировать CSS этой страницей. Проверить поиск, переходы страниц с сохранением контекста клиента, пустой список, длинные названия, настольный и мобильный размеры. Обнаруженные проблемы безопасности обработчика изменения связей вынести отдельно от оформления.
